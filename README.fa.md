# perso-match — جست‌وجوی درست، بدون تغییر متن اصلی

وقتی کاربر «علی» را جست‌وجو می‌کند ولی دیتابیس «علي» دارد، مقایسه معمولی ممکن است هیچ نتیجه‌ای ندهد. اعداد «۱۲۳»، «١٢٣» و «123»، اعراب عربی و نیم‌فاصله هم همین مشکل را ایجاد می‌کنند.

این پکیج یک کلید جداگانه برای جست‌وجو می‌سازد و محل نتیجه را روی متن اصلی برمی‌گرداند؛ بنابراین هایلایت هم درست می‌ماند.

```sh
npm install perso-match
```

```ts
import { createMatcher } from 'perso-match';
const matcher = createMatcher({ locale: 'fa' });
const text = '📦 كالا ۱۲۳ برای علي';
const ranges = matcher.find(text, 'کالا 123');
console.log(text.slice(ranges[0].start, ranges[0].end)); // كالا ۱۲۳
```

## کاربرد واقعی در دیتابیس

متن اصلی را در `display_name` نگه دارید و `matcher.key(name)` را در ستونی جدا مثل `search_key` ذخیره کنید. `matcher.profile` هم باید همراه آن ذخیره شود. یک ایندکس غیرمنحصربه‌فرد روی پروفایل و کلید بسازید؛ ورودی جست‌وجو را با همان تنظیمات تبدیل و با پارامتر SQL مقایسه کنید.

قبل از مهاجرت داده‌ها:

```ts
const groups = matcher.collisions(rows, row => row.name);
```

این تابع متن‌های متفاوتی را که کلید یکسان پیدا می‌کنند گزارش می‌دهد. هیچ رکوردی را ادغام یا حذف نمی‌کند. یکسان بودن کلید، دلیل یکسان بودن هویت اشخاص نیست.

## رفتار پیش‌فرض

- «ی/ي» و «ک/ك» هماهنگ می‌شوند.
- رقم‌های فارسی و عربی به رقم انگلیسی تبدیل می‌شوند؛ مقدار همچنان رشته است و صفر ابتدایی از بین نمی‌رود.
- اعراب رایج و کشیده از کلید حذف می‌شوند.
- نیم‌فاصله به فاصله تبدیل می‌شود: «می‌روم» با «می روم» تطبیق دارد.
- «أ/ا»، «ى/ي» و «ة/ه» به‌صورت پیش‌فرض یکی نمی‌شوند.
- متن اصلی و ایموجی‌ها حفظ می‌شوند.

برای تطبیق «میروم» با شکل‌های فاصله‌دار، `spacing: 'compact'` را صریحاً فعال کنید. این گزینه ممکن است واژه‌های مستقل را هم به هم بچسباند؛ نتیجه را برای بررسی نشان دهید، نه اینکه خودکار رکوردها را یکی کنید.

برای رابط کاربری از `matcher.parts(text, query)` استفاده کنید. هر بخش شامل متن اصلی و پرچم `match` است. با رندر عادی React یا `textContent` نمایش دهید؛ متن کاربر را وارد `innerHTML` نکنید.
